# Browser recovery: implications for the product-team system

September 15, 2026. Original objective remains a terminal-operated product department that owns judgment, delivery, maintenance and learning. Codeweb is the proving ground. These observations do not establish superior product judgment or unattended operation.

## What this run demonstrated

1. **Shared records reconcile chats; transcript memory does not.** This terminal cannot read the other chat's transcript. It found newer launch/overflow/correction evidence in existing COD-26/28/34 records and files. It reused those tasks rather than creating a parallel browser task. Read current status, active execution, newest comments by timestamp, and artifact hashes before deciding what remains.
2. **A capability belongs to an execution environment.** Installed Playwright/Chromium had failed in worker attempts, while the existing executable launched in this terminal without extra flags or security-setting changes. The precise earlier failure cause remains unproven. Record installed, launch-tested, workflow-tested and candidate-accepted separately, along with execution profile and evidence. Do not call a capability universally unavailable or working based on one environment.
3. **Recovery changes task dependencies.** COD-28 waited for COD-34 while a QA defect required COD-28 to change. The Product Lead removed the old blocker in a separate verified write, then restored the acyclic correction → capture → final-review chain. A later pointer-navigation failure reused that corrected chain. A 409 with unresolved prerequisites is not evidence that broader security permission is needed.
4. **Visual appearance and successful HTTP requests are insufficient.** Fresh screenshots showed the mobile hash wrapping correctly, but normal pointer actions exposed blocked homepage buttons. A diagnostic-only CSS override isolated the decorative hit-testing layer; it was not counted as a product pass. Tests retain normal clicks, overflow assertions and before/after hashes.
5. **The integration code also needs contracts.** An older handoff nested candidate metadata; its replacement used top-level fields. This terminal's receipt parsing failed after a successful comment POST. Readback confirmed the existing comment without reposting. An overly strict selection assertion also mistook an omitted terminal newline for lost recipe content. These were integration/test errors, not product defects. Preserve failed observations and calibrate the test rather than assign false product work.

## Larger direction

Keep Paperclip as the coordination backend for now. Native task creation, assignment, comments and dependency wakes are working. The observed problems point to execution adapters and handoff/recovery contracts, not yet a need to fork the project manager or build another queue.

The next system milestone should make the proven browser path requestable through a scoped, tested tool interface that workers can use, with a consistent candidate manifest and a native review/correction protocol. Inspect existing runtime/MCP capabilities before implementing an adapter. No new daemon, hosted service or security relaxation was created by this run.

A candidate handoff should consistently identify the objective/task, source revision or patch hash, generated-file hashes, execution owner/profile, allowed actions, actual checks/results and unresolved decisions. Validate its shape before executing or mutating state. Status clients must use explicit ordering and read-after-write verification instead of reconstructing current state from arbitrary message order.

## Next proof

One objective should request browser verification against exact bytes, receive a structured failure, route a bounded correction, reverify new bytes, obtain independent approval and select its next action without the founder coordinating tools or tasks. Record any terminal-root intervention, elapsed time and unavailable measurements. Do not call installed tools, drafted instructions or a single repaired product screen proof of an autonomous company.
