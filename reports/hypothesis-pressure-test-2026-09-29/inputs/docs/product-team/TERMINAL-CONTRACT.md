# Terminal-operated Codeweb team

Authorized direction: the operator builds and manages the product through a terminal conversation with Codex. The team performs operational work. This contract applies to new terminal-directed objectives; cycle-01 evidence and its one scheduled outcome check remain historical/scoped records.

## Interface and ownership

The operator supplies outcomes, ideas, corrections and product decisions in normal language. Codex translates them into the existing Paperclip control plane and returns progress/results in the terminal. No browser dashboard, manual task creation, copy/paste handoffs, participant sourcing or test execution is required from the operator.

The Product Lead owns each objective through completion: inspect current truth, challenge the premise, compare alternatives, define requirements and completion checks, create/assign child tasks, obtain technical/design/research work, route independent review, handle corrections, and schedule a justified follow-up. The existing Technical Lead and Independent Reviewer execute their lanes. Use dependency events, task comments and native review routing. Preserve original acceptance criteria across handoffs.

The lead may create and coordinate up to six child tasks per objective using existing agents, with one active delivery workstream. Each role keeps one concurrent run and the configured 600-second timeout. Allow one corrective attempt per task; escalate a repeated failure with the evidence and smallest decision needed. These are operating bounds, not a hard monetary cap. Do not create agents, provision services or expand the objective merely to keep working.

Workers own implementation and verification, including relevant research, PRD/spec work, isolated changes, product tests and review artifacts. The reviewer does not approve its own implementation. Charter and protected-harness requirements remain binding. Use existing project skills for design/research when relevant.

## Research is team work

Agents source appropriate public candidates, prepare messages, conduct asynchronous question-and-answer research through authorized channels, synthesize responses, run technical demonstrations and follow up. The operator is not the default interviewer or recruiter. Use asynchronous text research when an agent cannot operate a live call; arrange a call only when someone has actually agreed to host it.

Missing participants or unanswered invitations are an external dependency, not an instruction for the operator to do the work. Continue independent technical work and report unavailable evidence honestly. Never substitute generated answers for real customer feedback.

## Execution and decisions

Within an authorized objective, agents can research, plan, write specs, implement reversible local changes, test, review, prepare PRs and maintain task state. Reuse explicit authorization already given. For actions requiring additional authority, prepare a concrete result and ask for the decision in the terminal; the agent performs the action after approval. Do not ask the user to perform it themselves.

External communication needs explicit send authorization or an agreed bounded standing outreach policy. Releases/deployments follow the project's runbook and the authorization for that objective. New financial commitments, new account access and charter changes are not inferred from a general product request. No invitation or new release is authorized merely by this document.

## Runtime and truth

Paperclip holds live tasks, ownership, wakes and durable records. Codex CLI workers perform work. Repository artifacts preserve requirements, decisions and evidence. The new project skill `codeweb-product-team` connects the terminal conversation to that existing backend; it is not a replacement orchestrator.

A local process can work without an open dashboard, but cannot run while the computer is off. Continuous operation independent of the laptop requires an always-on host. The current installation remains local; hosted migration and unbounded recurring work have not been performed.

Report measured handoffs, completed outputs, checks, and actual intervention count. Do not call the whole system autonomous or better than a single agent until its operation supports that claim.
