# Private manual measurement setup

This packet provides an offline operating method, not a running pilot or telemetry system. Design rules are frozen; actual participant allocation and entry facts remain pending. The existing source candidate is approved only for its controlled eight-tool Codex MCP scope. At preparation there are zero screened/consenting/enrolled participants, zero observed changes and no named confirmed adjudicator. Existing product users and return remain unknown.

## What the files do

`protocol.md` and `rules.json` hold fixed definitions, assignment order, availability-only allocation fallback, correctness/harm rules and the original success threshold. `scripts.md` supplies seven neutral episode questions before a separate demo, granular consent, human adjudicator appointment and optional follow-up. `session-runbook.md` uses the approved local source build with Node ≥22 and participant-reviewed session changes, preserving competent controls. `READY-CHECK.json` distinguishes preparation from actual measurement readiness. `FREEZE.json` will name exact artifacts for separate critic review; the author does not self-PASS.

`templates/empty-ledger.json` is a blank structure, not a participant record or actual ledger. Create the actual working copy only in an agreed private location outside the public repository. JSON is authoritative for helper calculations; CSV templates are optional manual indexes, not a second source of truth. Never count rows of examples/templates as study evidence. Null means unknown or pending. A reviewed, justified not-applicable cost phase is distinct from null.

Use stable P-series participant, A-series human-adjudicator, S/R pair and case/effort/finding IDs. Do not encode real names, handles, file paths or company names into IDs. Identities and allowed contact routes belong only in the private contact crosswalk. Public leads can retain public source IDs in the private screening index; a lead ID is not a participant ID. Synthetic verification uses `SYNTHETIC-` IDs and `data_kind: synthetic_verification` only under `verification/`; it never enters actual ledgers or outcome records.

## Populate only from actual events

1. **Lead:** the prospect owner records a publicly sourced episode/profile, exact source link and last verification date, role/fit uncertainties, prior contact and proposed route. This is sourcing evidence, not a completed conversation or enrollment. A public profile/issue does not authorize outreach. Source validity and exact send authorization must be confirmed separately.
2. **Screened conversation:** after authorized contact and agreement to discovery, record when a real person completed the episode conversation and reviewed minimal notes. Source the answers to their actual episode; no agent-generated responses. Nonresponse, an unanswered invitation or an unavailable profile is not screened. In the JSON participant record, `screening.completed_at` refers to that actual event, and `notes_private_ref` points to permitted private notes.
3. **Qualified:** record ordinary maintainer role, usual Codex context, recent unresolved scope/reuse decision, authorized source, two distinct comparable upcoming changes and eligibility timestamp. Mark unknown/false honestly. Someone reporting competent native success without upcoming unresolved decisions is useful counterevidence but is not forced into the trial. Builders/reviewers/buyers remain auxiliary. Public facts alone do not fill private consent or source-authority fields.
4. **Consenting/enrolled:** record explicit observation, source/adjudicator access and session-install permission, timestamp, evidence reference, permitted access people and retention/withdrawal route. Verify the actual authorized contact route. Enrollment is a qualified consenting person included in the pre-outcome allocation; setup is a separate later stage. Follow-up, recording, optional selected counts and exact publication have independent choices. No automatic opt-in.
5. **Allocation and appointment:** fill the first natural-job slot in qualification order and apply its predefined condition order; availability-only fallback may change job composition before any outcomes. Assign two real different change IDs and a comparable-pair source reference. Freeze the whole actual allocation. Confirm actual named human adjudicator, availability/consent/source access and their separation from the decision maker. Keep their identity private and disclose conflicts. The participant confirms task scope and the adjudicator privately freezes a bounded source oracle before each task. Missing adjudication stays incomplete.
6. **Setup and case:** fill source byte receipt, Node/client/requested model/reasoning/parser identities and scope qualification only after actual readback. Confirm participant permissions and useful controls. Inspect actual frontend/control absence and actual treatment exposure; installed package or server nonlaunch alone is insufficient. Record source identity, condition/order, competent native stage plan, actual outcome/actions, all candidates/nulls/misses/harms, normal checks, judgments and facilitator help. Codeweb activation is an adjudicated useful source-backed treatment decision; native success, installation, first invocation and automatic output have separate fields.
7. **Cost:** use one unique effort row per actor's exclusive active/blocked interval. Map observed rows to every required phase; justify a phase with no work instead of inventing a zero. Include setup, map/refresh, permissions/recovery, source reading, author/reviewer/checks, facilitator and independent adjudication. Shared participant preparation is charged once to the first chronological case; Codeweb-only setup is charged fully to the first treatment case. Cohort-only logistics are separately retained in `cohort_effort` and total pilot effort. Record model wait/elapsed/token/byte/money availability separately; do not double count person/model waits or amortize over imagined future use.
8. **Follow-up:** if consented, record the participant-reviewed final observation of the agreed two-week window. Preserve actual eligible opportunity/use evidence in minimal private notes. One JSON final-window record per person summarizes any multiple underlying events; do not create repeated denominator rows. Known later eligible people form the denominator, including eligible access failures. Optional useful people form the numerator; prompted/automatic use, no opportunity and unknown/nonresponse stay visible separately. No known eligible denominator means an unobserved rate, not zero retention.
9. **Publication:** exact derivatives require exact participant approval where applicable, operator allowlist and privacy review. The default is false. Aggregates can identify a five-person cohort; do not assume anonymization authorizes publication. Private data/source/transcripts/contact/config and local Mac paths stay out of the repository. Do not publish this folder wholesale.

## Run the explicit-record helper

The helper uses standard-library Python, reads only the command-line ledger and adjacent `rules.json`, makes no network calls and collects no product or host data. It writes nothing; stdout is an **internal** aggregate with anonymous task IDs and no publication approval. It cannot authenticate a consent receipt, a person's identity or a human's independence; an operator must verify those facts.

After separate critic approval, acknowledge the exact rules SHA-256 in the actual ledger and record the protocol review reference. The reviewed freeze manifest supplies that hash. Do not set pending confirmations true to make a summary green.

Before running, record the required chronology with actual timestamped facts: `screening.completed_at <= qualified_at <= consent.consented_at < allocation.frozen_at < task_started_at`. The adjudicator's `consented_at <= availability_confirmed_at <= allocation.frozen_at` must hold. Each case's `source_identity_private_ref` is required, `source_identity_recorded_at` follows allocation and precedes `oracle.frozen_at`, and `oracle.source_identity_private_ref` must match that actual pin. Record `configuration.verified_at` after allocation and before the case starts. For treatment, `setup.started_at <= setup.confirmed_at <= configuration.verified_at < task_started_at`, with setup starting after consent/allocation. Native-first participants can install Codeweb between their distinct native and treatment cases. Decision-maker actor IDs are the enrolled participant IDs; adjudicator actor IDs are the appointed adjudicator IDs and must differ. Their actual effort rows must use those same associations. The helper rejects contradictory/missing fields; private source/consent/human facts still need operator verification.

```sh
python3 summarize.py /ABS/PRIVATE/ACTUAL-LEDGER.json
```

It reports all case/pair costs and treatment-minus-native differences, job subgroups, fixed-order groups, raw findings/misses/harms and known-eligible follow-up denominators. The primary comparison uses exact seconds for medians; display rounding never changes the gate. Incomplete consent/adjudication/costs/absence/exposure or fewer than five people/ten distinct changes cannot pass. Severe harm and incorrect final/acted-on decisions block. Missing optional tokens/money are unknown and cannot support a savings claim. Optional follow-up validation is reported separately from the ten-task gate.

An empty ledger reports `unobserved`, `proportion: null` and unknown observed effort. Record-count zero describes this study's preparation, not installed users or overall retention. Exit 0 means the JSON was handled without structural validation errors, **not** that the pilot passed; inspect `gate_status`. Exit 1 indicates invalid recorded fields; exit 2 indicates invalid input/rule identity. Synthetic data requires `--allow-synthetic`, is clearly labeled, and always reports `observed_customer_outcomes: false`.

The 44 focused verification cases cover consent/routes, appointment/independence, source/permission/control/exposure requirements, fixed allocation/order, incomplete/duplicate changes, exact gate/median/setup costs, exclusive actor intervals, severe/unresolved harm, faster incorrect decisions, pure time-saving separation, optional follow-up denominators and empty-data semantics. The twelve added checks correct independent critic findings on screening/qualification/consent chronology, actual source pins, decision ownership and directly related setup/appointment dates/actor associations. They are synthetic software verification, not human benefit. The first 23-file frozen packet and prior outputs remain unchanged under `iteration-01`; the latest manifest covers only current author artifacts. The files under `verification/` never contain real participants.

## What this learns without telemetry

Manual consented observations can establish the episode, actual useful decision, source correctness, harmful/noisy cases, total task effort, setup friction and optional later use when an opportunity is actually known. They cannot establish the full installed population, passive return, unseen tasks or PMF. Full stats/pending-card/history/graph/source/transcript exports are unnecessary.

If a participant independently chooses to share selected reviewed aggregate counts, retain separate consent, exact selected fields/window, their review and the undercount/automatic-output limitations. Do not convert local `regressionsFlagged` to bugs prevented or edited-file correlations to causal benefit. `briefInjected` drives session/week dates, so hook-disabled Codex MCP-only work supplies no valid session-return proxy. Public npm downloads, stars and forks provide surface counts; for example a download total is not a user count. The primary gate remains observed decisions, independent source adjudication and full measured effort.
