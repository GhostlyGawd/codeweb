Problems with detecting some of the generated Lombok methods occur in both VSIX and JDTLS variants.
Probably I shouldn't post this here into 050_configuration.md.
Its a deal for another issue I suppose.
get_symbols_overview, find_symbol
YES Generated classes (*Builder, Fields, *BuilderImpl)
YES Generated fields ($lock, log, builder storage like name, retries$value)
NO Generated methods (getX/setX, builder(), toBuilder(), withX, equals/hashCode/toString, host()/tag()/build(), fluent accessors, prefix-stripped accessors, @Delegate methods)
YES Generated constructors (@AllArgsConstructor, @StandardException, @RequiredArgsConstructor synth)
find_referencing_symbols
YES On user-written sources (fields, classes, your own methods) — call sites of the generated API are returned correctly
YES On generated fields (log, $lock)
Partially on generated classes (e.g. *Builder) — sometimes returns false positives (unrelated .toString() matches)
NO On generated methods/constructors — they are not addressable because find_symbol can't return them
replace_symbol_body, insert_before_symbol, insert_after_symbol
YES User-written symbols
NO  Anything Lombok-generated
search_for_pattern, replace_content (regex / text-based)
YES Everything, including generated APIs — this is the only way to reach generated methods/constructors
Compilation, diagnostics, completion, hover, and go-to-definition from a call site are all driven by jdtls bindings and cover the full Lombok API. You won't see this through serena tools, but if mvn test-compile is green, jdtls already resolved everything.
